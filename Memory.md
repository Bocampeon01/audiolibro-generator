- **Bloqueante grave: no se puede compilar el APK en esta PC con Flutter/Gradle de Windows.** Error: `java.io.IOException: Unable to establish loopback connection` / `UnixDomainSockets.connect... Invalid argument`. Diagnosticado a fondo: es un bug de AF_UNIX sockets roto a nivel Windows en esta maquina (build 10.0.26200, canal Insider/Canary) — confirmado con Java puro (TCP loopback anda, AF_UNIX no) en 3 versiones de JDK distintas (17.0.10, 17.0.20, 25). Se descarto: vEthernet (Default Switch) deshabilitado, antivirus de terceros (no hay, solo Defender), `netsh winsock reset` + reboot (tampoco arreglo).
- **Solucion que funciono: compilar el APK desde dentro de WSL2** (Ubuntu 26.04 instalado), que corre su propio kernel Linux y no sufre el bug de AF_UNIX de Windows. Setup: JDK 17 instalado en WSL (`apt install openjdk-17-jdk-headless`, corrido como root via `wsl -u root` para evitar pedir password interactivo), Android SDK reutilizado desde Windows via `/mnt/c/Android/Sdk` (con `ANDROID_HOME`/`ANDROID_SDK_ROOT` apuntando ahi), proyecto Flutter copiado a filesystem nativo de WSL (`~/audiolibro/android_app`, NO en `/mnt/d/...` — sockets Unix no andan bien sobre NTFS/DrvFs). Flutter de Windows (`/mnt/c/src/flutter`) no sirve desde WSL por line-endings CRLF en los scripts .sh; hubo que instalar un Flutter Linux nativo separado en `~/flutter` dentro de WSL.

## 2026-09-23 (continuacion 2) — Voces multiples, mas idiomas, texto sincronizado
Pedido del usuario: (1) elegir voz hombre/mujer y mas de una opcion por idioma, (2) ver el texto resaltado mientras se escucha, (3) sumar idiomas (eligio portugues BR, frances, italiano, aleman).
- **Voces**: `detect_lang.py` paso de un dict lang->voz unica a `VOICES: dict[str, list[dict]]` con 2 voces por idioma (id Piper + label). Catalogo elegido a mano usando nombres de voces Piper conocidos por genero (en_US-hfc_female/male son explicitas; el resto -daniela, siwis, tom, paola, riccardo, thorsten, kerstin, faber, jeff- por convencion de nombre, sin metadata de genero real en el catalogo de Piper). 11 voces nuevas descargadas (~650MB) en `voices/`.
- **Idiomas**: soportados ahora es/en/pt/fr/it/de. `chapters.py` CHAPTER_PATTERN extendido con "chapitre/capitolo/kapitel". langdetect ya devuelve los codigos ISO correctos para estos, no hizo falta tocar la deteccion.
- **Texto sincronizado**: se evaluo usar `include_alignments` de Piper (alineacion fonema-por-fonema, confirmado que existe en la API) pero se decidio NO usarlo — mapear fonemas a palabras exactas es fragil y no estaba probado. En cambio: **sintesis por oracion**. Pipeline nuevo: `sentences.py` (split por puntuacion) -> cada oracion se sintetiza individual -> `wav_utils.concat_wavs` las concatena en el wav del capitulo (copia de frames PCM, sin reencode, todas las oraciones comparten sample rate porque es la misma voz) y devuelve los offsets -> `build_m4b` reproyecta esos offsets a tiempo absoluto del libro y escribe sidecar `{title, chapters, sentences: [{text, start_ms, end_ms}]}`.
- Contra: generar tarda mas (una llamada a Piper por oracion en vez de por capitulo). No medido pero aceptable para libros de prueba.
- **Web**: nuevo endpoint `GET /api/voices` (catalogo idioma->voces), `/api/generate` acepta `voice` ademas de `lang`. `/api/library` aligerado (solo `chapters_count`, no el array completo) + nuevo `/api/library/{filename}/meta` que devuelve el sidecar completo (chapters+sentences) — separado de la lista para no mandar todas las oraciones de todos los libros en un solo listado.
- **Android**: `Sentence` model nuevo, `Book` parsea `sentences` del sidecar. `PlayerScreen` suma boton (icono articulo, arriba derecha, solo si hay `sentences`) que abre panel de texto scrolleable con la oracion actual resaltada (filtradas por capitulo actual, no todo el libro de una), auto-scroll via `GlobalKey`+`Scrollable.ensureVisible`. Tocar una oracion hace seek ahi. `library_service.dart` ahora pide `/meta` aparte al descargar (antes venia embebido en el listado).
- Probado end-to-end en emulador: descarga libro con voz Daniela (es_AR) via servidor, abre reproductor, activa "seguir texto", play, el resaltado avanza de oracion en oracion en tiempo real junto con el audio. Confirmado visualmente con screenshots.
- Pendiente: no se probaron todavia pt/it/de con audio real de punta a punta (solo es/en/fr), ni la calidad de las voces de menor calidad (it_IT-riccardo-x_low, de_DE-kerstin-low).
